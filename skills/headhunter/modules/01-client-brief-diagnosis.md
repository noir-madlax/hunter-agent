## Skill 1: 客户需求澄清与职位诊断

### Purpose

帮助客户澄清招聘需求，识别岗位真实目标、核心胜任力、候选人画像和招聘难点。

### When to Use

当用户提供职位需求、JD、招聘背景、客户信息或希望分析某个岗位时使用。

### Process

0. **前置（强制）**：先跑 module 00.5 (JD 信号反演)，把"假设清单"作为本模块输入。
1. 分析客户业务背景：行业、发展阶段、产品或业务模式、当前组织问题、招聘岗位产生原因。
2. 拆解职位信息：岗位名称、汇报对象、团队规模、核心职责、业务目标、绩效指标、任职资格。
3. 在进入人才地图和找人前，补齐公司/团队背景：业务模式、团队结构、招聘原因、当前痛点、未来 6-12 个月交付目标、COE/SSC 支持程度、目标/排除公司背景。
4. 识别显性要求：年限、行业经验、职能经验、管理经验、专业技能、语言要求、学历要求、地域要求。
5. 识别隐性要求：文化匹配、老板风格、抗压、变革、从 0 到 1 / 从 1 到 N、稳定性、候选人动机。
6. **失败模式预演 (Pre-mortem)**：在输出画像前，先回答三层失败问题（见下节）。
7. 输出职位画像。

### Failure Mode Pre-mortem (三层)

在岗位还没招人前，先回答："这个岗位最可能怎么失败？" 不是列困难，而是找机制。

#### Layer A：岗位设计层
- 这个岗位本身有没有结构性矛盾？（例："招管培做一号位"、"5-7 年做 COO-2"、"全球岗但只列国内大厂背景"）
- 多个发展方向并列时，是真的轮岗 or 雇主自己也没想清楚？
- 层级 × 预算 × 经验组合在市场上是否存在？

#### Layer B：候选人留存层
- 什么背景的人进来 6 个月内最可能想走？为什么？
- 入职后真实工作和 JD 描述的落差在哪里？
- 现有团队对"空降高潜"的接纳度如何？

#### Layer C：雇主预期层
- 用人方对这画像的真实预期，是否和 JD 一致？
- 多个 stakeholder（CEO / COO / HR / 用人 leader）的期望是否对齐？
- 客户上一次招类似岗位的失败原因是什么？
